## 1. Decidir: precisa de i18n?

| Situação | Faça |
|---|---|
| Produto só pt-BR, sem plano concreto de outro idioma | **Não instale lib de i18n.** Formate tudo com `Intl` via `format.ts` usando uma constante `LOCALE = 'pt-BR'`. |
| Cliente já fala em outro idioma, público estrangeiro, app em loja de vários países | **i18n desde a primeira tela.** Migrar depois custa caçar cada string no projeto inteiro. |
| Dúvida | Pergunte ao cliente antes de começar. É decisão de escopo, não de código. |

Mesmo sem i18n, as regras de layout da §9 e de formatação da §5 valem sempre: nomes longos e fonte ampliada quebram tela do mesmo jeito que tradução.

## 2. Stack e setup (Expo / React Native)

Padrão da casa: **i18next + react-i18next + expo-localization**.

```bash
npx expo install expo-localization i18next react-i18next
```

```ts
// src/i18n/index.ts
import i18n from 'i18next';
import { initReactI18next } from 'react-i18next';
import { getLocales } from 'expo-localization';
import ptBR from './locales/pt-BR';
import en from './locales/en';

export const IDIOMAS = ['pt-BR', 'en'] as const;
export type Idioma = (typeof IDIOMAS)[number];

export const resources = { 'pt-BR': ptBR, en } as const;

function idiomaDoAparelho(): Idioma {
  for (const l of getLocales()) {
    if ((IDIOMAS as readonly string[]).includes(l.languageTag)) return l.languageTag as Idioma;
    const base = IDIOMAS.find((i) => i.startsWith(l.languageCode ?? '')); // "pt-PT" → "pt-BR"
    if (base) return base;
  }
  return 'pt-BR';
}

i18n.use(initReactI18next).init({
  resources,
  lng: idiomaDoAparelho(),
  fallbackLng: 'pt-BR',
  defaultNS: 'common',
  interpolation: { escapeValue: false }, // React já escapa
  returnNull: false,
});

export default i18n;
```

Importe `@/i18n` (arquivo `src/i18n/index.ts`) uma vez no `src/app/_layout.tsx`, antes de qualquer tela. Se o usuário escolheu idioma manualmente, `usePreferencesStore.getState().language` tem prioridade sobre `idiomaDoAparelho()`. Plurais usam `Intl.PluralRules`, que o Hermes suporta nas versões atuais do React Native; se algum plural sair errado num aparelho antigo, confira a versão do RN antes de instalar polyfill.

### Chaves tipadas

Com isso, chave errada vira erro de TypeScript em vez de texto "alunos.lista.vazo" aparecendo para o usuário:

```ts
// src/i18n/i18next.d.ts
import 'i18next';
import type ptBR from './locales/pt-BR';

declare module 'i18next' {
  interface CustomTypeOptions {
    defaultNS: 'common';
    resources: typeof ptBR;
  }
}
```

## 3. Organização dos textos

Um **namespace por feature** mais um `common`. pt-BR é o idioma-fonte: é nele que se escreve primeiro, e é ele que tipa as chaves.

```
src/i18n/
  index.ts
  i18next.d.ts
  locales/
    pt-BR/
      index.ts        # export default { common, alunos, auth }
      common.json     # Salvar, Cancelar, erros de rede, estados genéricos
      alunos.json
      auth.json
    en/
      ...mesma estrutura
```

```json
// locales/pt-BR/alunos.json
{
  "titulo": "Alunos",
  "lista": {
    "vazio": {
      "titulo": "Nenhum aluno ainda",
      "descricao": "Cadastre um aluno para começar a montar suas turmas.",
      "acao": "Cadastrar aluno"
    },
    "contagem_one": "{{count}} aluno",
    "contagem_other": "{{count}} alunos"
  },
  "excluir": {
    "confirmar": "Excluir {{nome}}? O histórico de pagamentos também será apagado.",
    "botao": "Excluir aluno",
    "sucesso": "Aluno excluído."
  }
}
```

Chave descreve **onde e para quê** (`lista.vazio.titulo`), não o texto (`nenhumAlunoAinda`). Quando o texto muda, a chave continua fazendo sentido.

O vocabulário oficial (`guia-visual.md`) vira um **glossário por idioma**: "Aluno" = "Student", "Turma" = "Class". Tradutor e IA seguem o glossário, senão a mesma entidade ganha três nomes em inglês.

## 4. Escrevendo textos traduzíveis

```tsx
const { t } = useTranslation('alunos');

<Text accessibilityRole="header">{t('titulo')}</Text>
<Text>{t('lista.contagem', { count: alunos.length })}</Text>
<Text>{t('excluir.confirmar', { nome: aluno.nome })}</Text>
```

Regras, com o motivo:

1. **Nunca concatene frase.** `t('ola') + nome + t('bemVindo')` quebra em idioma com outra ordem de palavras. Use interpolação: `t('saudacao', { nome })`.
2. **Plural pela lib**, nunca `count === 1 ? ... : ...`. Há idiomas com três ou mais formas de plural.
3. **Frase inteira numa chave.** Negrito ou link no meio da frase: use `<Trans>` do react-i18next, não quebre em pedaços.
4. **Não reaproveite chave por coincidência.** "Abrir" de porta e "Abrir" de arquivo podem ter traduções diferentes. Uma chave por contexto.
5. **Texto de acessibilidade também traduz**: `accessibilityLabel`, `accessibilityHint`, alt de imagem, anúncios de leitor de tela.
6. **Nada de texto dentro de imagem.** Não dá para traduzir nem para o leitor de tela ler.
7. **Sem gíria e trocadilho** em texto de sistema (erro, botão, confirmação). Não sobrevive à tradução.

## 5. Datas, números, moeda e fuso

Formate sempre com `Intl` recebendo o idioma atual; nunca monte `dd/mm/aaaa` na mão.

```ts
// src/utils/format.ts — versão multi-idioma do template format.ts da expo-app
import i18n from '@/i18n';
import { getCalendars } from 'expo-localization';

const locale = () => i18n.language;
const fuso = () => getCalendars()[0]?.timeZone ?? 'America/Sao_Paulo';

export const formatData = (iso: string | Date) =>
  new Intl.DateTimeFormat(locale(), { dateStyle: 'short', timeZone: fuso() }).format(new Date(iso));

export const formatDataHora = (iso: string | Date) =>
  new Intl.DateTimeFormat(locale(), { dateStyle: 'short', timeStyle: 'short', timeZone: fuso() }).format(new Date(iso));

// moeda é do NEGÓCIO, não do idioma: preço em real continua em real para quem usa o app em inglês
export const formatMoeda = (valor: number, moeda = 'BRL') =>
  new Intl.NumberFormat(locale(), { style: 'currency', currency: moeda }).format(valor);

export const formatNumero = (n: number) => new Intl.NumberFormat(locale()).format(n);

export const formatRelativo = (iso: string | Date) => {
  const diffMin = Math.round((new Date(iso).getTime() - Date.now()) / 60000);
  const rtf = new Intl.RelativeTimeFormat(locale(), { numeric: 'auto' });
  if (Math.abs(diffMin) < 60) return rtf.format(diffMin, 'minute');
  if (Math.abs(diffMin) < 1440) return rtf.format(Math.round(diffMin / 60), 'hour');
  return rtf.format(Math.round(diffMin / 1440), 'day');
};
```

- **API e banco em ISO 8601 com fuso** (UTC ou offset explícito). A conversão para o fuso do usuário acontece só na tela.
- **Moeda não muda com o idioma.** Trocar para inglês não converte R$ em US$.
- CPF, CNPJ, CEP e telefone BR são formatos do **dado**, não do idioma: continuam com máscara brasileira em qualquer idioma.

## 6. Validação e erros de API

Com i18n, o schema zod guarda a **chave** da mensagem, e o componente de campo traduz:

```ts
nome: z.string().trim().min(3, 'validacao.nomeCompleto'),
```

```tsx
// no FormInput (src/components/forms/form-input.tsx — expo-app, formularios.md)
const { t } = useTranslation();
{error?.message ? <Text>{t(error.message, { defaultValue: error.message })}</Text> : null}
```

O `defaultValue` faz mensagem ainda não migrada para chave continuar aparecendo como texto, o que permite migrar aos poucos.

Erros do backend: o contrato padrão da casa já traz `code` (`{ code, message, fieldErrors }`). O app traduz pelo código (`t(`erros.${error.code}`)`) dentro do `getUserMessage`, com fallback para a mensagem genérica por tipo de erro — o texto fica todo no front, num lugar só. Se o backend também precisa responder no idioma (e-mails, PDFs), mande `Accept-Language` nos headers do `api-client.ts`.

## 7. Troca de idioma

Padrão: segue o idioma do aparelho. Ofereça seletor manual em Configurações só se o público realmente precisa (turista, empresa multinacional).

```ts
// guarde a escolha no store de preferências (src/stores/preferences-store.ts — expo-app)
await i18n.changeLanguage('en');
usePreferencesStore.getState().setLanguage('en');
```

No boot, use o idioma salvo se existir; senão, o do aparelho. Depois de trocar, invalide queries cujo conteúdo vem traduzido do backend (`queryClient.invalidateQueries()`).

## 8. Textos nativos (permissões, nome do app)

Mensagens de permissão do iOS e o nome do app sob o ícone não passam pelo i18next; são do sistema. No Expo, configure `locales` no `app.config.ts` apontando para um JSON por idioma com as chaves nativas (ex.: `CFBundleDisplayName`, `NSCameraUsageDescription`). Confira o formato atual na documentação do Expo ("Localization"). Mudança aqui exige build novo, não vai por OTA.

Ficha da loja (descrição, capturas de tela) também é por idioma: planeje junto com a tradução do app.

## 9. Layout que aguenta tradução

- Texto traduzido costuma ser **mais longo** que o português (alemão e finlandês chegam a +30–40%) ou bem mais curto. Botão com largura fixa corta.
- Nada de `width` fixo em botão, chip ou aba com texto; nada de `numberOfLines={1}` em texto essencial.
- Linha com rótulo + valor vira coluna quando não cabe (mesma regra do texto ampliado em `acessibilidade.md` §6).
- Use `start`/`end` (`marginStart`, `paddingEnd`) em vez de `left`/`right` desde o começo. Custa zero agora e deixa o app pronto para idioma da direita para a esquerda (árabe, hebraico) se um dia precisar.
- **Pseudo-idioma para testar**: um locale de desenvolvimento que alonga e marca cada texto (`[!! Àļũñõš ~~~ !!]`). Qualquer texto que aparecer sem os colchetes está fixo no código; qualquer texto cortado mostra layout frágil.

```ts
// só em desenvolvimento
const pseudo = (s: string) => `[!! ${s.replace(/[aeiou]/g, (v) => v + v)} ~~~ !!]`;
```

## 10. Web sem Expo

Na Web (Expo): mesmo i18next; o `lang` do `<html>` vem do `+html.tsx` (`expo-app/references/web.md`) e deve acompanhar o idioma ativo.

## 11. Checklist

```text
[ ] Decisão registrada no guia-visual: só pt-BR ou multi-idioma
[ ] Nenhum texto de UI fixo no componente (se multi-idioma) — inclusive labels de acessibilidade
[ ] Interpolação no lugar de concatenação; plural pela lib
[ ] Datas, números e moeda via format.ts com Intl; API em ISO com fuso
[ ] Moeda do negócio, não do idioma
[ ] Erros de validação e de API traduzíveis (chave ou código)
[ ] Glossário do vocabulário oficial por idioma
[ ] Tela testada com pseudo-idioma: nada cortado, nada fixo
[ ] Textos nativos (permissões, nome do app) e ficha da loja por idioma
```
